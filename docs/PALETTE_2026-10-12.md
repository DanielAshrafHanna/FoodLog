# White, Teal & Taupe palette

Dany supplied Dusty Taupe `#A78C76`, Dark Teal `#073D4A`, and Turquoise Surf `#1EA1C2`, explicitly retaining white and allowing additional colors.

| Role | Light | Dark |
| --- | --- | --- |
| Canvas | `#F7F8F8` | `#071E25` |
| Reading surface | White | `#0D2C35` |
| Primary action | Dark Teal + white text | Turquoise Surf + deep teal text |
| Action hover | `#0B5263` + white | `#43BAD5` + deep teal |
| Selection | `#E5F1F3` | `#18424D` |
| Accent text | `#09768F` | `#73D4E8` |
| Warm supporting surface | `#F4EEE9` | `#2D2A28` |
| Primary text | `#142F38` | `#F2F7F8` |
| Supporting text | `#52676E` | `#A8C0C7` |

White on Dark Teal has 11.83:1 contrast. White on Turquoise Surf has only 3.03:1, so filled turquoise controls use dark text. Light small accent text uses a deeper turquoise. Dark small accent text uses a lighter turquoise, separate from action fills. Input/control borders use `#758F99` in light mode and `#557A85` in dark mode for at least 3:1 contrast against their surfaces. Taupe is kept for warmth and rating marks; small warm text on white uses `#765C48` rather than the source taupe.

The authoritative palette in `styles.css` maps the four source primitives to existing semantic roles and restaurant/dish component tokens. Browser theme color, install canvas, and offline colors follow the palette. Error/destructive reds remain semantic colors. Branding assets, typography, list spacing, borderless close/bookmark controls, data, and interaction behavior remain unchanged.

Local fixture screenshots cover desktop, 390px, and 320px in light/dark mode under `docs/audit-screenshots/2026-10-12/palette-*.png`. No production records are used for validation.
