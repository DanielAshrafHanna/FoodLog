# Phone dish-photo flicker — 3 November 2026

Status: local implementation, uncommitted/unpushed. Dany identified dish photographs on phones as the affected surface. No production data, permission, schema, upload or deployment change.

## Reproduced cause

The reconciliation cache remembered outer section markup but did not initialize the authored signatures of the nested dish cards/carousels. Mounting a carousel adds runtime touch-readiness attributes and changes pagination controls. On the first fresh dish update, the fallback compared that mounted DOM against a new unmounted template and treated unchanged cards as different. A changed card also replaced its entire photo subtree when only the review or actions had changed.

In a 390px local fixture, changing one review replaced **all four dish cards and all eight image elements**. This can discard already-decoded image elements and make the photos blink when opening-time/background data arrives. It is not an image upload problem. Ordinary first-time network loading is distinct and still depends on connection/cache state.

[Reproduction script](reproduce.mjs), [baseline node identities](baseline-continuity.json), [fixed node identities](final-continuity.json). Run a local preview on 4186; `CONTINUITY_PHASE=baseline` routes only the committed `f0ead1f` detail reconciler from Git, while the default runs the current code. All records/images are disposable fixtures and external requests are blocked.

## Fix

- Remember authored markup before mounting changes runtime attributes, limited to the boundaries actually used for reconciliation.
- Retain an existing dish-card element for the same dish ID, synchronize its authored attributes, and reconcile its children in place.
- Keep an unchanged photo carousel and its images attached when review/Like/action content changes. Existing native listeners, decoded images, focus and saved photo position remain.
- Replace the affected carousel when its actual photo markup/order changes; removal, main-photo selection and full-screen viewing remain current. Entire removed dishes still leave the DOM.

No image-ready delay, blanket eager loading, thumbnail-quality reduction, animation timing change, layer hint or upload/recovery change was added. The source change is scoped to `lib/detail-view.js`.
