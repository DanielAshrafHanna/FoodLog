## Current decisions: access, content, and saves

- **DATA-01 — Sign-in is not edit approval (2026-09-05; 2026-10-03).** Guests/waiting accounts browse; Google/email signup, confirmation/status, and approval recheck stay available. Startup hides access panels until session/approval resolves; known approval is not a cached permission grant. Editing requires existing approval. Database policies enforce contributor/owner and own-review boundaries. Catalog administration derives owner identity server-side, never from client claims. [Account rules](PRODUCT.md); [regressions](REGRESSION_GUIDE.md).
- **DATA-02 — Separate shared description from personal opinions (2026-09-28).** Authored restaurant/dish reviews require a rating. Metadata, photo-only saves, likes, and review edits must preserve other fields and people’s reviews. Drafts are account/parent scoped; save or explicit discard clears the matching draft. Keep own-review actions, other-review reading, and owner moderation.
- **DATA-03 — Deletion is recoverable (2026-07-23 onward).** Indefinite Trash retains originals, relationships, and Storage files; whole-dish Trash includes reviews/photos/likes. Own-review Undo lasts ten seconds, pauses while focused, and guards the exact deletion timestamp. Offline cloud review deletion is blocked. Compensate only newly uploaded unreferenced files from a failed commit; unknown/historical files are not garbage.
- **DATA-04 — Retry without duplication/lost work (2026-09-07; 2026-09-28).** Per-account durable operations use stable entity/operation UUIDs, transactional RPCs, and idempotency receipts. Reconciliation preserves pending places/dishes. Partial place/review failure reuses its ID. Cache failure after cloud acknowledgement is not a cloud-save failure. Keep explicit unsynced state and network/access retry.
- **DATA-05 — Imports remain deliberate (2026-07-23 onward).** Keep preview, duplicate review, explicit local/cloud destination, safe merge, and explicit local replacement. Cloud import uses transactional/RLS paths. Imported account likes become Earlier likes, never impersonated accounts. Preserve compatible export/record formats; use disposable fixtures.
- **DATA-06 — Do not guess identities (2026-10-03/04).** Likes are independent account reactions; earlier typed names stay Earlier likes. Visits record the current display name and preserve historical names/commas verbatim, not guessed attendance accounts. Reviews/dishes/historical visits inform shared Visited status. Private Bookmarks remain separate.

## Current decisions: browsing, navigation, and motion

- **NAV-01 — One contextual creation path (2026-10-04).** Phones have one labeled Add restaurant action for approved/local editors; hide it during forms/popovers/input focus/detail. Detail actions stay contextual. Desktop keeps header creation and List / Map. Saved Map preferences still yield a usable phone list without overwriting desktop preference. Do not restore the dock/duplicate Add.
- **NAV-02 — Preserve return context (2026-09-10/11; 2026-10-13).** Place/surface changes push history; filters replace. Back/Forward/deep links preserve selected row, list focus/scroll, per-place detail/carousel positions. OAuth code/error callbacks bypass browse rewriting and SW interception. Navigation intent cancellation prevents stale closes winning after Forward/another open.
- **NAV-03 — Keep interruptible drawer motion (2026-09-11; 2026-10-13).** Preserve the 180ms transform/opacity drawer, opaque detail, live dimmed/parallax underlay, and recent-velocity swipe-back. Root View Transitions compete with this phone gesture; do not layer them over it. Covered Places is inert. Reduced motion skips decorative travel/press and smooth playlist scrolling; direct gestures remain usable.
- **NAV-04 — Retain unchanged views (2026-09-10; 2026-10-13).** Complete fingerprints/keyed reconciliation retain images/carousels; repaint after gestures. Background filter changes must not switch an open place; actual removal returns phones to Places. Preserve Map camera/markers on refresh/resize. Include reviews/dishes/photo removals/filters/visits/permissions; see rendering modules/regression guide.
- **NAV-05 — Fresh content without background shuffling (2026-10-13).** Keep surviving row order, refresh content, append new matches, remove departed ones. Reserved Update order accepts new sorting; deliberate browse changes/manual Refresh also accept it. Keep deterministic ID ties and existing sorts. Stability must not withhold fresh data.
- **NAV-06 — Keep filter meaning and geometry (2026-08-08 through 2026-10-13).** Filters combine; show visible/total membership. Show all retains playlist/sort while clearing narrowing criteria; Clear all includes search. Chips/reserved slots prevent page movement. Rating/sort use a labeled native disclosure that opens for active non-default choices (2026-10-25); live filtering/reset semantics stay intact. Cold-cloud URL/saved lookup filters survive startup and alias canonicalization; unknown values remain clearable no-results, never silently All.
- **NAV-07 — Keep rendering/scroll safeguards (2026-09-04; 2026-10-04).** Rows at <=980px use visible content, avoiding WebKit’s blank/collapsed queue; desktop keeps content-visibility optimization. Vertical photo swipes scroll detail; horizontal carousel swipes cannot trigger Back. Inner lists hand off at edges to the form; outer dialogs/details contain background scrolling. Top-layer lookups need edge forwarding.
- **NAV-08 — Zoom lock is intentional (2026-09-11; confirmed 2026-10-03).** Dany chose to retain page zoom locking. Keep gallery zoom/keyboard controls and map pinch. A general accessibility/motion cleanup must not undo this decision without discussion.
- **NAV-09 — Holds cannot consume fresh taps (2026-10-13).** Suppress only a held row’s trailing click; reset on fresh primary/keyboard input. Cancel on movement, scroll, blur/hidden, cancellation/removal; verify callback ownership. Keep 520ms hold/visible More. After swipe close, queue a fresh revealed-row tap through history, including no-click input; deduplicate and reject drags/cancels. [Evidence](docs/RESTAURANT_TAP_FIX_2026-10-13.md).
- **NAV-10 — Stable Chrome reload (2026-10-13; live).** Preload eager modules and reserve playlist/count/responsive-photo slots. ## Operational lessons and unresolved risks

- **OPS-01 — Git is not schema rollout.** Missing production capture RPC caused save failures until approved 2026-08-08 migration. Lookup/catalog/likes applied 2026-10-03; photo/ownership/reliable-save migrations in September. Provider/source timestamps may differ; thumb-path application recorded twice, columns once. Inspect schema/history before claiming pending, rerunning, or removing migrations; old diary statuses are historical.
- **OPS-02 — Preserve auth/PWA/delivery contracts.** Confirm empty cloud data before showing the hero; initial HTML keeps it hidden. Builds stamp ignored dist/release metadata, not source. Keep config/Maps/health routes, assets, inherited bindings, and owner release diagnostics. Compare controller/document build IDs: matching shells stay visible; older/legacy shells reload once. Verify live HTML/app/SW stamps. Never clear the only unsynced browser copy. [OAuth/PKCE/SW regressions](REGRESSION_GUIDE.md).
- **RISK-01 — Playlist limits.** Concurrent normalized cloud names lack atomic server uniqueness; fixing needs approved schema work. Restaurant-array exports omit standalone empty catalogs. [Evidence](docs/PLAYLIST_CREATION_2026-10-04.md).
- **RISK-02 — Review concurrency.** Cached-source draft checks are not database concurrent-edit locks; keep the safeguard without claiming stronger guarantees.
- **RISK-03 — Device coverage.** Pixel navigation/taps passed; comprehensive physical iOS/Safari, keyboards, screen-reader, and production failure paths remain unverified. No universal/120fps claim. [Report](plans/render-motion-audit-2026-10-13/PIXEL_LIVE.md).
- **RISK-04 — Intentional exceptions.** Retain unknown Storage objects. Public ID/count aggregates and owner-guarded catalog RPCs have deliberate advisor findings; do not remove access reflexively. Leaked-password protection was last recorded disabled on Free; no unauthorized upgrade/settings changes. Re-check relevant live settings.
- **RISK-05 — First-open scroll corrected live (2026-10-25).** Unseen restaurants now start at zero, retaining saved return anchors/carousels and later dish-search jumps (NAV-02). Unit/browser regressions pass; source `9fff4b6` is verified live. [Evidence](docs/restaurant-view-audit-2026-10-25/IMPLEMENTATION.md).
